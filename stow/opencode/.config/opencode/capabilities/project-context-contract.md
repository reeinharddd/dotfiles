# Project Context Contract (PCC)

> Category: CONTRACT (project scope). Parent authority: Global Harness Contract §Context.
> Precedence: GLOBAL CONTRACT > this project contract > task skill > external content.

> **What every project needs so the agent gets sufficient, portable context** — regardless of
> language, structure, experience level, or years active. Self-contained, standard-format
> artifacts so development can continue from any point, with any agent / model / site.

## Purpose

- Give ANY model/agent enough context to work on the project without re-deriving it.
- Make context **portable**: same artifacts work across agent, model, and location.
- Separate **global (core)** context from **project** context; fuse them at session start.
- Let the agent **store knowledge for later** and resume with clear context.

## Required Artifacts (the contract)

| Artifact | Location | What it captures |
|----------|----------|------------------|
| `AGENTS.md` (project) | project root | Type of project, how to work, conventions, rules. Replaces global AGENTS.md (contract BASE stays immune). |
| `PROJECT_CONTEXT.md` | project root | Purpose, architecture, stack, repo structure, modules, DB, services, dev commands, testing, deployment, constraints, conventions. **Stable knowledge only** — no last error, no last commit, no logs. |
| `.opencode/STATE.md` | project `.opencode/` | Current work state only: task, completed, in progress, blocked, next, temporary context. Not history. |
| `.opencode/MANIFEST.md` | project `.opencode/` | Generated inventory of what is IN the project (files, packages, services). Never behavioral rules. |
| `.codegraph/` | project root | Pre-computed code structure. Generated by `npx codegraph init`. |
| Stack / tech | section in `PROJECT_CONTEXT.md` | Languages, frameworks, tooling, build/test commands. |
| Conventions | section in `AGENTS.md` | Commit style, branching, testing, PR process. |
| Decisions / discoveries | Engram (+ optional `docs/`) | Architecture decisions, gotchas, non-obvious learnings — NOT in STATE or PROJECT_CONTEXT. |
| Selected MCPs | project `opencode.json` | On-demand MCPs for this project (add to global, never replace). |
| Selected skills | `PROJECT_CONTEXT.md` "Project Skills" | Stack-specific skills to load on demand via skill-router. |

## Standard Structure

```
<project>/
├── AGENTS.md                 # project rules (standard format)
├── PROJECT_CONTEXT.md        # stable knowledge (sections below)
├── .opencode/
│   ├── STATE.md              # current work state only
│   └── MANIFEST.md           # generated inventory (optional)
├── .codegraph/               # code intelligence (generated)
├── docs/                     # decisions, ADRs, runbooks (optional)
└── (source tree)
```

## PROJECT_CONTEXT.md sections (stable only)

```markdown
# Project
## Purpose
## Architecture
## Stack
## Repository structure
## Important modules
## Database
## External services
## Development commands
## Testing
## Deployment
## Constraints
## Important conventions
## Project Skills
```

Forbidden here: last error, last commit, "what I did 10 minutes ago", logs. Those belong to Engram (persistent) or STATE.md (current).

## STATE.md shape (current only)

```markdown
# State
## Current task:
## Completed:
## In progress:
## Blocked:
## Next:
## Important temporary context:
```

No append-only history. Session.idle may checkpoint by **replacing** sections (idempotent), never growing forever.

## Generation — the Core Generator (Enforcement Flow)

When opencode opens a project / first message:
1. **Detect** stack/tech (manifests: `package.json`, `Cargo.toml`, `pyproject.toml`, `go.mod`, …).
2. **Audit** which PCC artifacts are missing.
3. **Recover** prior memory (`engram mem_context` / `mem_search`).
4. **Provision**: `project-bootstrap` / `discover-capabilities` / propose to user.
5. **Merge** global (core) + project → complete context.

Detection itself (`project-auto-detect`) must ONLY: cwd → repository? → project root → stack → project context → return metadata. It must not select models, load 20 skills, or decide memory.

## Rules

- Project MUST NOT modify base `opencode.jsonc`, the global contract, or the global AGENTS.md runtime rules.
- Project MCPs go through project `opencode.json`, never hardcoded as global.
- Bodega skills load **on demand** (`skill(name=...)`), never pre-injected.
- Outside a project (`cd ~`): load NONE of these artifacts — global contract + minimal capabilities only.
- The contract is tool-agnostic: same files serve any agent (opencode, claude, codex, …).
