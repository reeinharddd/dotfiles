# Project Context Contract (PCC)

> **What every project needs so the agent gets sufficient, portable context** — regardless of
> language, structure, experience level, or years active. Self-contained, standard-format
> artifacts that capture each part of the project (type, how to work, conventions, knowledge) so
> development can continue from any point, with any agent / model / site.

## Purpose
- Give ANY model/agent enough context to work on the project without re-deriving it.
- Make context **portable**: same artifacts work across agent, model, and location.
- Separate **global (core)** context from **project** context; fuse them at session start.
- Let the agent **store knowledge for later** and resume with clear context.

## Required Artifacts (the contract)
| Artifact | Format | What it captures |
|----------|--------|------------------|
| `AGENTS.md` (project) | Markdown, frontmatter | Type of project, how to work in it, conventions, rules. Replaces global AGENTS.md (BASE PROTOCOL stays immune). |
| `PROJECT_CONTEXT.md` | Markdown, under `.opencode/` | Detected stack, language, frameworks, test runner, package manager, selected project skills/MCPs. |
| `.codegraph/` | SQLite knowledge graph | Pre-computed code structure (symbols, edges, callers). Generated by `npx codegraph init`. |
| Stack / tech declaration | section in `PROJECT_CONTEXT.md` | Languages, frameworks, tooling, build/test commands. |
| Conventions | section in `AGENTS.md` | Commit style, branching, testing, PR process. |
| Decisions / discoveries store | `engram` memory + optional `docs/` | Evolving decisions (architecture, config), gotchas, non-obvious learnings. |
| Selected MCPs | `opencode.jsonc` per project (via dotfiles) | Which on-demand MCPs apply (e.g. `royal-mcp` for WP). |
| Selected skills | `PROJECT_CONTEXT.md` "Project Skills" | Stack-specific bodega skills to load on demand. |

## Standard Structure (functional)
```
<project>/
├── AGENTS.md                 # project rules (standard format)
├── PROJECT_CONTEXT.md        # stack + selected skills/MCPs
├── .codegraph/               # code intelligence (generated)
├── docs/                     # decisions, ADRs, runbooks (optional but recommended)
└── (source tree)
```

## Generation — the Core Generator (Enforcement Flow)
When opencode opens / first message in a project, the core audits against this contract and
**generates missing artifacts from real context**:
1. **Detect** stack/tech (manifests: `package.json`, `Cargo.toml`, `pyproject.toml`, `go.mod`, etc.).
2. **Audit** which PCC artifacts are missing.
3. **Recover** prior memory (`engram mem_context` / `mem_search`).
4. **Provision**: `project-bootstrap` (writes `PROJECT_CONTEXT.md`), `discover-capabilities`
   (finds unregistered skills/MCPs/binaries), or propose to the user.
5. **Merge** global (core) + project → complete project + user context.

## Rules
- Project MUST NOT modify base `opencode.jsonc` or the global AGENTS.md BASE PROTOCOL.
- Project MCPs go through dotfiles, never hardcoded in project config.
- Bodega skills are loaded **on demand** (`skill(name=...)`), never pre-injected.
- The contract is tool-agnostic: same files serve any agent (opencode, claude, codex, kiro…).
